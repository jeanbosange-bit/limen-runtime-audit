# extract_core reconstruction report

## Verdict

`PARTIALLY_REPRODUCIBLE`

All `extract_core.py` outputs that feed Phase 9 are replay-validated across all eight
historically successful models. The overall script is classified partial because two
full-panel processes terminated under allocator instability, the script-emitted
final-layer rows do not generally equal the compact table's retained generation-logit
`FINAL_NATIVE` rows, and the separate geometry-destroying/final-packaging stages were not
part of this replay.

Current Phase 9 numerical results remain supported.

## Replay execution

The recovered script was materialized byte-for-byte and compiled successfully. The replay
launcher recovered exact archived dependency bodies, redirected output/scratch/import
paths only, and left extraction logic unchanged.

Two full-panel attempts reproduced the historical early row counts and allocator failures
but terminated without a caught Python exception before normal writer closure. Their
partial parquets were preserved and excluded from comparison. Because the archived resume
logic can overwrite part files, those attempts were not resumed.

Each of the eight historically successful models was then executed in a fresh isolated
process. This changed model orchestration only; each model retained the historical runs,
tensors, checkpoint, formulas, seeds, strides, schemas, and extraction function. All
isolated writers closed normally.

## Mismatches and boundaries

### Direct versus packaged dtype/serialization

The recovered direct schemas write projection values as float64. Historical packaging
later recast them to float32 and rewrote parquet files. After that documented cast, every
projection and rotated value is exactly equal. This cannot change the existing geometry
or decodability results because the canonical inputs are precisely the validated float32
values.

### Script-labeled `FINAL_NATIVE`

The script recomputes selected final-layer rows through final norm + LM head and labels
them `FINAL_NATIVE`. The compact table retains dense `FINAL_NATIVE` values from captured
generation logits. Qwen's 397 rows match; the other seven models differ across probability,
logit, token/rank, and entropy fields, sometimes substantially. This is a pipeline-source
difference, not serialization noise.

Evidence-supported impact:

- Geometry findings: unaffected; projection rows match exactly after cast.
- Decodability findings: unaffected; projected-H rows match exactly.
- Orthogonal-invariance result: unaffected for rotated inputs; rotated rows match exactly.
- Geometry-destroying control: not directly replayed; its validated upstream projections
  reduce but do not eliminate its separate provenance requirement.
- Phase 9 readout: unaffected; Phase 9 explicitly filters `INTERMEDIATE_PROJECTED`, whose
  31,329 rows match exactly.
- Atlas scalar comparisons: not generated by `extract_core.py`; no impact inferred.
- RPTA interpretation: final-native and intermediate-projected layers must remain separate.
  This mismatch reinforces that boundary but does not establish a mechanism.

### Full-panel execution instability

The inability to complete one continuous full-panel replay is operational evidence against
`FULLY_REPRODUCIBLE` for the script as an end-to-end monolithic run on this Jetson state.
It does not create a numeric mismatch in the isolated successful-model outputs.

## Scientific conclusion

The compact projected-H, orthogonal-rotation, and intermediate-readout data used by Phase
9 are supported by zero-difference replay validation. No missing model or cell was repaired.
The current Phase 9 numerical results therefore remain supported. Separate validation is
still required for the geometry-destroying-control builder and final packaging pipeline.
